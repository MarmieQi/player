# 玩家 ID 存在性查询 API

`player-presence` 用于判断一个 Minecraft 玩家 ID 是否曾出现在指定服务器的玩家日志中。它适合 AstrBot 入群审核、管理命令和其他只需要确认玩家 ID 是否存在的服务。

## 请求

```http
GET /api/stats/player-presence?playerName=Steve&serverId=main
X-Player-Stats-Key: <AstrBot 插件密钥>
```

也可以使用管理员登录后的 Bearer Token：

```http
Authorization: Bearer <管理员登录令牌>
```

不要把插件密钥放在 URL 查询参数中。

### 查询参数

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `playerName` | 是 | Minecraft 玩家 ID。服务端会去除首尾空白，并进行忽略大小写的完整匹配；不会把 `Steve2` 匹配为 `Steve`。 |
| `serverId` | 否 | 服务器 ID，例如 `main` 或 `sub`。省略时查询所有服务器的历史档案；当天日志兜底只检查当前已启用的服务器。建议业务已经知道目标服务器时始终传入。 |

## 成功响应

找到玩家时返回 `200 OK`：

```json
{
  "playerName": "Steve",
  "servers": [
    {
      "serverId": "main",
      "serverName": "主服",
      "playerName": "Steve",
      "firstSeenAt": "2026-09-06T16:01:00"
    }
  ]
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `playerName` | 日志或玩家档案中保存的玩家 ID 原始大小写。 |
| `servers` | 确认出现过该玩家的服务器列表。 |
| `firstSeenAt` | 当前数据来源中能确认的首次出现时间。数据库命中时是历史首次出现时间；当天日志兜底命中时是当天快照中的首次匹配时间。无法解析时间时可能为 `null`。 |

调用方判断玩家存在时，应以 HTTP `200` 且 `servers` 非空为准。

## 查询顺序与当天数据

接口按以下顺序查询：

1. 查询 MySQL 中的 `player_server_profiles` 历史玩家档案。
2. 只有历史档案完全未命中时，才读取当天 SMB 日志快照作为兜底。
3. 当天日志按玩家名称列进行精确匹配，找到首条记录后停止扫描。

因此，当天首次出现、尚未经过正式日志导入的玩家也可以被查到。这个接口用于“是否存在”判断；如果玩家已经在任意历史档案中命中，接口不会额外扫描当天日志来补全他今天首次出现的其他服务器。

当天日志兜底与后台日志查询、公开坐标日志查询共用同一个 `liveLogSnapshotCache`：

- 按服务器 ID 缓存快照。
- 同一服务器并发刷新时只会有一个请求读取 SMB，其他请求等待并复用结果。
- 默认缓存 120 秒，可通过 `PLAYER_LOGS_LIVE_CACHE_SECONDS` 调整，允许范围为 10-600 秒。
- 缓存期间新写入的日志最迟会在下一次快照刷新后可见。
- 请求被取消或超时时，文件扫描会及时停止。

## 状态码

| 状态码 | 含义 | 调用方建议 |
| --- | --- | --- |
| `200` | 已确认玩家存在。 | 可以继续业务流程。 |
| `401` | 插件密钥或管理员身份无效。 | 视为配置错误，不要判定玩家不存在。 |
| `404` | 数据库未命中，并且有效目标服务器的当天日志已成功检查但也未命中。不存在对应的 `serverId` 时也返回此状态。 | 可以判定当前数据中不存在该玩家；若由用户传入 `serverId`，调用方应先保证它是有效配置值。 |
| `500` | 数据库或服务端内部错误。 | 视为无法确认，记录错误并稍后重试。 |
| `503` | 历史档案未命中，同时当天 SMB 日志暂时无法读取或扫描。 | 视为无法确认，不要误判为玩家不存在。 |

错误响应统一为：

```json
{
  "timestamp": "2026-09-06T09:01:00Z",
  "message": "当天日志暂时不可用，无法确认玩家是否存在"
}
```

## 调用示例

```bash
curl --fail-with-body \
  -H "X-Player-Stats-Key: $PLAYER_STATS_KEY" \
  "http://127.0.0.1:9493/api/stats/player-presence?playerName=Steve&serverId=main"
```

调用方应设置合理的连接和总请求超时。AstrBot 当前默认使用 5 秒超时，并将除 `404` 之外的失败响应视为“无法确认”。
